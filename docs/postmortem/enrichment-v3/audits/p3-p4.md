## Phase 3 — Prompt identity

### 1. "One unchanged prompt yields ONE hash across providers." — **MET (near-vacuous as tested)**
- `compute_prompt_hash(prompt, schema_version)` (`prompts.py:39`, delegating to
  `seam.prompt_identity`, `seam.py:184`) takes **no model/provider argument** —
  the guarantee is structural. `legacy_prompt_hash`/`prompt_identity_v1`
  (`prompts.py:57`, `seam.py:195`) retain the old model-bound rule separately.
- Test `tests/unit/enrichment/test_prompt_identity.py::test_same_prompt_schema_same_hash_across_models_and_providers`.
- **Vacuity flag:** the test's "across providers" loop asserts
  `compute_prompt_hash(_PROMPT, IG_GOLD_SCHEMA_VERSION) == h_a` — the *same
  deterministic call repeated*. It is a tautology; it cannot fail unless someone
  re-adds a model parameter, at which point the changed signature is the real
  signal, not the assertion. The criterion is met because the signature cannot
  fork, not because the test detects a fork.

### 2. "`schema_version` participates in identity; a schema change re-hashes." — **MET**
- `test_hash_varies_with_schema_version` (`test_prompt_identity.py:60-70`):
  asserts `compute_prompt_hash(_PROMPT,"1") != compute_prompt_hash(_PROMPT,"2")`
  and 5 distinct versions → 5 distinct hashes. This test genuinely could fail
  (e.g. if version were dropped from the payload) — falsifiable, not vacuous.

### 3. "The migration for existing `prompt_hash` values is versioned or verified-by-test, never applied silently." — **PARTIALLY MET**
- **What is verified by test:** `legacy_prompt_hash` reproduces the old scheme
  `sha256(f"{prompt}:{model}")[:16]` exactly
  (`test_prompt_identity.py:97-113`), and new vs legacy hashes differ
  (`:118-141`). Detectability is real.
- **Live-corpus verification (this audit, read-only queries):** all **9,576**
  `gold_analyses` rows carry exactly one hash `24c8e291fdfc28ed`, which equals
  `legacy_prompt_hash(IG_GOLD_PROMPT, 'gemini-3.5-flash-lite')` computed today;
  **0 rows** carry the new hash `7a68d264dd8284d8`. So the entire legacy corpus
  is correctly distinguishable, and the drain's staleness logic
  (`instagram/assets.py:1195,1215` — `prompt_hash = CURRENT_PROMPT_HASH` guard)
  does flag the whole corpus as re-enqueue-eligible. The behaviour matches the
  plan's intent.
- **What is missing:** there is **no versioned migration** (no script, no ADR
  step, no reconciliation runner) — only a documented procedure in the
  `prompts.py:12-26` docstring ("identify → verify → set prompt_hash"). Nothing
  applies it and no test exercises the re-hash of an existing row; the criterion's
  "versioned or verified-by-test" is satisfied only in the weak "the boundary
  hash is verified-by-test" sense, not "the migration is verified".
- **Contradiction found:** 8 of the 9,576 rows have `model = NULL` yet carry the
  same legacy hash. The documented identification step
  `legacy_prompt_hash(prompt, model)` cannot reproduce a hash for a NULL model —
  the reconciliation procedure silently fails on those 8 rows as written.

## Phase 4 — Silver conform (the five tables)

### 4. "Five tables exist, keyed `(post_id, platform)`, each with its own `prompt_hash`/`model`/`schema_version`/`run_id`." — **UNMET (test-world only)**
- Schemas with exactly those provenance columns exist in code
  (`conform.py` `_PROVENANCE`, `TABLE_SCHEMAS`) and are exercised by fixtures in
  `tests/unit/enrichment/test_conform.py`.
- **Live system: nothing exists.** `data/state.duckdb` has none of the five
  tables (queried above); `data/lake/silver/` has none of the five Parquet
  files; `register_conformed` has no production caller. The tables exist only
  where a test creates them. This is the criterion's plain words — "five tables
  exist" — failing against the live database.

### 5. "Re-running conform makes ZERO API calls, proven by a real run." — **UNMET**
- The proof that exists is `test_zero_api_calls_enforced_structurally`
  (`test_conform.py:247-300`): an **AST import-graph scan** asserting conform's
  transitively reachable local imports contain no provider/HTTP module. That is
  a structural argument, and the test's own docstring concedes it ("conform's
  import graph must not contain…").
- The criterion explicitly demands **a real run**. No real run exists: live
  bronze has 0 rows, conform has never executed outside tests. The structural
  scan is decent belt-and-braces but is exactly the "AST/import scan" the audit
  brief said not to accept in place of the criterion. (It is also leaky by
  design: stdlib `urllib`/`socket` exclusion is implicit and dynamic imports
  would evade the scan.)

### 6. "A deliberately malformed bronze row dead-letters loudly (not silent NULL)." — **PARTIALLY MET (destination is a dead end)**
- Mechanism exists: quarantine rows written to
  `silver_enrichment_quarantine` with machine-readable `reason_code`
  (`conform.py:77`, reason codes `:184-195`, `_quarantine_row`), plus
  `logger.warning`; fixtures prove malformed JSON/enum/length rows quarantine
  with no silently-NULL conformed row (`test_conform.py:317-345`).
- **But "loudly" fails at the destination:** nothing in production reads
  `silver_enrichment_quarantine` (confirmed by [`../reviews/architecture-soundness.md`](../reviews/architecture-soundness.md)
  §1: "consumer NONE NAMED — no ADR declares the table, its schema/key, its
  retention, or its triage consumer"). `register_conformed` does register it
  (`conform.py`, `for tid in (*SILVER_TABLES, SILVER_QUARANTINE)`), but no view,
  check, dashboard, or retry driver queries it. Per the audit brief's own bar —
  "to a destination that a real consumer reads, or to a table nothing queries" —
  this is a write to a table nothing queries. The warning log is the only
  observable signal, and there is no check that fires on quarantine growth.
- All proof is fixture-based (only possible — live bronze is empty).

### 7. "Carousel cross-field check (`n == len(image_summaries)`) fires on a real violation." — **UNMET (fixture-only)**
- Implemented for real: `conform.py:453-513`, the `n == len(image_summaries)`
  check at `:499-506`, reason-coded `cross_field_violation`.
- Proven only by `test_conform.py::test_carousel_conforms_when_counts_match` and
  the violation tests — **hand-built fixtures**. "A real violation" (a genuine
  provider response with a mismatched carousel) has never been observed: there
  are zero bronze rows, conform has never run on live data. The criterion's word
  "real" is unmet; the check exists but its firing on reality is untested and
  untestable until real enrichment runs.

## Unfalsifiable-as-written
- **P3 #1** as tested: the "across providers" assertion is a same-call
  tautology. Falsifiable form would require two call paths that could in
  principle diverge (e.g. two adapters each reporting their prompt identity).
- **P4 #6 "loudly"** has no operational definition — no consumer, no check, no
  threshold. As written, a silent log line satisfies it; any test of "loud"
  would need a named consumer to observe.

## Priority findings
1. **BLOCKER (P4):** the entire conform layer is unwired — no asset, no caller,
   no tables, zero bronze rows. Four of four Phase-4 criteria are satisfied at
   best in fixtures. Nothing here can be called MET until one real bronze row
   flows through `conform` into `data/lake/silver` and `data/state.duckdb`.
2. **HIGH (P4 #5):** replace the AST scan with a real double-run against a
   live bronze corpus asserting zero provider SDK imports at runtime (e.g.
   audit-trail/monkeypatch counter), as the criterion itself demands.
3. **HIGH (P4 #6):** name a consumer for `silver_enrichment_quarantine` (retry
   driver or triage view + asset check on quarantine growth); "loudly" is
   currently a log line nobody reads.
4. **MED (P3 #3):** the migration exists only as a docstring procedure; add a
   versioned migration script or a test that re-hashes a sampled legacy row —
   and handle the 8 `model IS NULL` rows the documented identification step
   cannot match.
5. **LOW (P3 #1):** strengthen the provider-independence test to something
   falsifiable (assert the seam's adapters report identical identity, or keep
   and reframe as structural).
