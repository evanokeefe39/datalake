# WATCHDOG.md — advisor review guidance

Terse, concrete risks for a second-pair reviewer. Not for the main executor;
captures project-specific traps and boundaries too noisy for AGENTS.md.

## Schema catalog is the single source of truth

- `src/datalake/defs/common/schemas.py` defines every table **once** as a
  `Table` spec (columns + constraints). Runtime DDL is generated by
  `duckdb_ddl()` / `sqlite_ddl()` — **never** hand-write a `CREATE TABLE` in an
  asset, worker, or migration. A hand-written DDL is how the catalog drifted
  (`dead_letter.failed_at` vs `created_at`, missing `video_duration_seconds`).
- Adding a column: add it to the spec, then `duckdb_ddl()`/`sqlite_ddl()` pick
  it up. The `tests/operational/test_ddl_builder.py` test fails if the generated
  DDL and the catalog disagree.
- Type maps (`DUCKDB_TABLES` / `SQLITE_TABLES`) are **derived** from the specs —
  the `str`-only shape is a backward-compat artifact, not the source of truth.

## Load-bearing invariants (do not break)

- `processed_on` is **first-seen only**. It is stamped when a post first lands
  in silver and never re-stamped. The dedup carries it forward via
  `fill_null(…).max().over("post_id")` — do not reintroduce a re-stamp path.
- Watermark discovery: `WHERE processed_on > watermark`. Reset = `DELETE` the
  watermark row, never a mass `UPDATE`.
- `dead_letter` is the **terminal** state (attempts >= `MAX_ATTEMPTS`). No
  automatic retry; `retry_dead_letter` is explicitly deferred.

## Media byte cache (the expiry-race fix)

- Instagram CDN URLs die in ~4-5 days. Media **bytes** are cached at scrape time
  in `ig_posts_slv` (via `cache_media_bytes` → `media_cache` table → local file
  under `data/media/posts/`). The worker's `lookup_or_upload_all` uploads from
  the **local cache** and falls back to the live CDN **only** on a cache miss.
- Do not make `lookup_or_upload_all` download from the CDN as its primary path —
  that silently re-introduces the expiry race for backlogged batches.
- `media_files` is a JSON list of URLs; `media_count` is its length. The byte
  cache is keyed by `url_hash(url)` (SHA-256 of the URL), not content.

## Gemini API footguns

- `media_resolution` must be the SDK enum string `"MEDIA_RESOLUTION_LOW"` (not
  `"low"`). The bare string form raises `400 INVALID_ARGUMENT` at call time.
- Two 429 subtypes: `insufficient_quota` (RPD) halts the batch and reschedules
  without burning attempts; `rate_limit_exceeded` (RPM/TPM) retries per-item
  with jittered exponential backoff. Quota reschedules must **never** increment
  `batch_items.attempts`.

## Operational state

- Never commit `data/ops.sqlite` / `data/state.duckdb`.
- `scripts/migrate_creators_profiles.py` mutates live ops state (drops
  `scrape_targets`, recreates batch tables). Do **not** run it against live
  `data/ops.sqlite` without explicit approval. The live DB currently carries
  two known local-only drifts this test suite flags: the vestigial
  `scrape_targets` table and a missing `batch_items.scheduled_for` (self-heals
  on the next batch/worker run).

## Test boundaries

- `tests/operational/test_state_compatibility.py` runs against the **live**
  `data/ops.sqlite` + `data/state.duckdb`, not a temp DB. A failure there is
  drift, not a bug in the test.
- `tests/unit/enrichment/test_media_cache.py` mocks `google.genai.Client`; keep
  the File API upload path exercised there so the CDN-vs-cache branch stays
  covered.
